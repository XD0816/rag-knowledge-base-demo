# 企业智能知识库问答平台

一个基于 **RAG（Retrieval-Augmented Generation，检索增强生成）** 架构的政企内部知识库问答系统演示项目。

**纯前端实现 · 零后端 · 零安装 · 双击即用**

---

## 快速开始

1. 双击打开 `index.html`（推荐 Chrome / Edge）
2. 点击左侧 **「一键载入示例文档（3 份制度）」**
3. 在右下角输入问题，例如：`出差住宿标准是多少？`
4. 展开回答下方的 **「引用来源」**，核对答案对应的原文片段

> 首次打开无需联网：TailwindCSS、pdf.js、mammoth 均已内置在 `assets/vendor/` 目录。
>
> 不想 clone 仓库？直接下载根目录的 [`rag-knowledge-base-demo.zip`](./rag-knowledge-base-demo.zip)（0.67MB），解压后双击 `index.html` 即可。

## 功能清单

| 模块 | 能力 |
| --- | --- |
| 文档接入 | 支持 PDF / Word(.docx) / TXT / MD，点击或拖拽上传，单文件 ≤ 20MB |
| 文档处理 | 自动完成 解析 → 文本清洗 → 语义切片 → 向量化 → 建立索引 |
| 知识库管理 | 文档列表、切片数统计、单文档删除、一键清空、知识库概览 |

| 历史问答 | 自动记录，支持一键回填到对话窗口 |
| 本地持久化 | 文档、切片、历史、设置全部存于 localStorage，刷新不丢失 |
| 生成引擎 | 默认本地抽取式引擎；可选接入任意 OpenAI 兼容大模型 |

## 技术栈

- **界面**：HTML5 + TailwindCSS（本地内置，离线可用）+ 原生 CSS 设计系统
- **逻辑**：原生 JavaScript（ES5 语法，无构建、无框架、无模块加载器）
- **PDF 解析**：[pdf.js](https://mozilla.github.io/pdf.js/) 3.11
- **Word 解析**：[mammoth.js](https://github.com/mwilliamson/mammoth.js) 1.6
- **存储**：localStorage
- **检索**：自研 TF-IDF 特征哈希向量 + BM25 混合检索

## RAG 流程实现

```
用户提问
   │
   ├─[1] 问题向量化 ──────────────┐
   │                              │
   ├─[2] 向量检索 Top-K ──────────┤  index.html 打开时由切片文本重建
   │        （余弦相似度 + BM25） │
   │                              │
   ├─[3] 片段过滤与排序 ──────────┘
   │
   ├─[4] 句子级抽取 + 答案组织（本地引擎）
   │      或 拼接 Prompt 调用大模型（可选）
   │
   └─[5] 渲染答案 + 引用溯源卡片
```

### 1. 语义切片（`text.js`）

- 先按空行切分段落，超长段落再按句子重组
- 聚合到约 **380 字 / 片**，相邻切片保留 **70 字重叠**
- **重叠窗口对齐到句子边界**，避免切片从半句开始（残句会显著拉低检索质量）

### 2. 向量化（`embedding.js`）

真实 RAG 使用 BGE / text-embedding 等模型产出稠密向量；本项目为了「零后端、可双击运行」，采用**特征哈希（Hashing Trick）**方案：

1. 中文按 **字符二元组（bigram）** 分词，无需词典，适合制度类长文本
2. **TF-IDF 加权**后映射到固定 **1024 维**空间（FNV-1a 哈希 + 符号位，降低哈希冲突偏差）
3. **L2 归一化**，余弦相似度退化为向量点积，检索 O(N) 但常数极小

> 接口形态与真实向量库一致：`embed(text) → cosineSearch(query)`。
> 替换为真实 Embedding 模型时，只需重写 `_embedTF` 一个方法。

### 3. 混合检索（`embedding.js`）

单一向量检索对精确关键词不敏感，因此叠加 **BM25**：

```
score = 0.68 × cosine  +  0.32 × bm25_norm  +  精确短语加成
```

低于阈值 `0.08` 视为不相关；返回后再按「相对最优分的 55%」二次过滤，
并优先采信主文档片段，避免噪声片段污染答案。

### 4. 答案生成（`rag.js`）

**默认：本地抽取式生成引擎（完全离线，绝不编造）**

1. 用 **IDF 加权 BM25** 对候选句子打分（而非简单词覆盖率）
2. 识别问题焦点（数量/时限、是否、列举、流程）并给对应句子加权
3. 把分号切碎的并列条款 **合并回完整一条**（如住宿标准的（一）（二）（三））
4. 按「相关度」排序，取 Top 4 组织为：结论句 + 要点列表，逐句标注 `[n]`

**可选：接入真实大模型**

点击右上角齿轮 → 填写 `Base URL / API Key / Model`（OpenAI 兼容协议）。
接入后走标准 Prompt 工程（强约束"仅依据资料回答 + 必须标注引用"），
**调用失败自动降级回本地引擎**，保证演示不中断。

### 5. 引用溯源（`app.js`）

- 答案中 `[1]` 角标与下方引用卡片一一对应，点击可定位高亮
- 引用卡片展示：来源文件、页码、相关度百分比、原文片段（关键词高亮）
- 从机制上解决大模型幻觉：**每句结论都能被追溯到一个可核对的原文档片段**

## 数据流与存储说明

- **向量不落盘**：localStorage 只保存文档元数据 + 切片文本，页面启动时毫秒级重建索引。
  这样同样容量可存 4 倍以上的文档（若存 1024 维 Float32 向量，14 个切片就要 56KB）。
- **存储上限**：浏览器 localStorage 约 5MB，约可容纳 150 万字文本；超限时会提示清理。
- **隐私**：所有解析、切片、向量化均在浏览器本地完成，文件不会上传到任何服务器。

## 关于"模拟"的边界（面试可讲）

| 环节 | 本项目实现 | 生产环境替换为 |
| --- | --- | --- |
| 文档解析 | pdf.js / mammoth（真实可用） | 同左，或后端 Unstructured / MinerU |
| 切片 | 段落聚合 + 句子边界对齐（真实可用） | 同左，可加语义切分 |
| Embedding | TF-IDF 特征哈希（可用的稀疏语义近似） | BGE-M3 / text-embedding-3 等稠密向量模型 |
| 向量库 | 内存数组 + 余弦点积 | Milvus / Qdrant / pgvector |
| 检索 | 向量 + BM25 混合 | 同左 + Rerank 模型（bge-reranker） |
| 生成 | 抽取式模板（离线、零幻觉） | GPT-4o / DeepSeek / Qwen（已预留接口） |
| 存储 | localStorage | PostgreSQL + 对象存储 |

**设计取舍**：Demo 的目标是「打开就能演示完整链路」，所以把重依赖（模型、数据库）
替换成浏览器内可运行的等价实现，但**保留了 RAG 每个环节的真实结构与接口**，
迁移到生产时是「换实现」而不是「重写架构」。

## 常见问题

**Q：PDF 解析出来是空的？**
扫描版 PDF 是图片，没有文本层，需要 OCR。本项目未集成 OCR，会提示"未能提取到有效文本"。

**Q：旧版 .doc 能传吗？**
不支持，请用 Word 另存为 `.docx`。`.doc` 是二进制复合文档格式，浏览器端解析成本高。

**Q：为什么答案看起来像"原文摘录"？**
本地引擎是**抽取式**的：只从检索到的片段中挑选句子并组织，不做自由生成。
这是刻意的取舍——保证零幻觉、可溯源。需要更自然的表述时，接入大模型即可。

**Q：接入大模型后报跨域错误？**
浏览器直连需要 API 服务端允许 CORS。若接口不支持，请保持关闭，使用本地引擎。

## 面试演示脚本（建议 3 分钟）

1. **打开页面** → 说明技术选型：纯前端、零依赖、双击即用
2. **点击「一键载入示例文档」** → 指出左侧切片数、向量维度实时统计
3. **提问「出差住宿标准是多少？」** → 指出 RAG 过程标签（检索 3 个片段 / 耗时）
4. **展开引用来源** → 强调 `[1]` 角标与原文一一对应，这是解决幻觉的关键
5. **提问「报销流程是什么样的」** → 展示流程类问题的不同组织方式
6. **追问一个知识库里没有的问题** → 展示兜底话术，说明"不知道就说不知道"
7. **点击右上角齿轮** → 说明可无缝切换真实大模型，失败自动降级
